# RPI Planning Handoff

## Decision Context

* **ADR ID:** ADR-0001
* **ADR:** docs/planning/adrs/0001-choose-agentic-hr-architecture.md
* **Status:** proposed
* **Compact summary:** adr-0001-compact-summary.md

The proposal establishes a reference baseline, not implementation approval. Plan against the selected components while preserving the ADR's unresolved decisions and measurable criteria.

## Engineering Work Stubs

1. Define the service and MCP tool contracts for ticket creation, approval, HRIS/ERP access, Microsoft Graph actions, and policy retrieval. Include tenant, user, role, and ownership context in authorization checks before every tool operation.
2. Specify ticket lifecycle and persistence boundaries across ticket/audit data and conversation memory. Define idempotency, concurrency, retention, recovery, and a tamper-evident audit design; Cosmos DB alone does not establish immutability.
3. Define the SLA event lifecycle for reminders and escalations, including duplicate-safe delivery, retries, dead-letter handling, and observable failure recovery. Do not implement timer thresholds until HR resolves the discrepancy between the 48-business-hour reminder/72-hour escalation in SOP-HR-042 and the 48-hour escalation shown in SPEC-HRIS-014.
4. Build verification plans for tenant and role isolation, manager direct-report scoping, policy citation quality, sensitive-field redaction, ticket workflows, and the PRD latency/availability targets.

## Suggested Acceptance Outcomes

* Unauthorized cross-tenant, cross-role, or non-direct-report access is denied in release-candidate tests.
* Ticket and approval actions are attributable, duplicate-safe, and recoverable after worker or queue retries.
* Audit records have a documented append-only or tamper-evident control beyond the Cosmos DB product choice.
* SLA behavior is not enabled until an authorized HR owner confirms the timer semantics.
* The PRD's p95 latency, availability, and auditability targets are measured with named test conditions.

# HR Copilot Solution Traceability Matrix

## Status and Scope

This matrix connects the supplied research, draft PRD, draft experience pack, planned architecture, proposed ADR-0001, and publication-boundary notes. It is an artifact review, not implementation, deployment, policy approval, or production-readiness evidence. The underlying SOP and ticket specification are explicitly synthetic workshop materials. The PRD and experience pack remain drafts, and ADR-0001 is proposed rather than adopted.

The matrix treats a link as **explicit** only when the source artifact names the related rule, requirement, journey, component, or criterion. A plausible relationship without an explicit test or evidence is marked **partial** or **gap**, not counted as verified coverage. No code or system behavior was tested.

## Marketplace and Publication Gates

Neither channel is a runtime component or a substitute for tenant consent, configured connectors, or operational readiness.

## Missing Links and Unmapped Components

1. **SOP-to-test gaps:** No acceptance criteria for overtime eligibility, pre-approval, emergency submission time, multipliers, hour caps, PTO accrual calculation, notice tiers above two days, blackout periods, certificate submission deadline, emergency retroactive leave, or leave/timezone calendar behavior.
2. **Role/privacy test gaps:** No explicit negative tests for tenant isolation, employee peer-data denial, manager non-direct-report denial, stale hierarchy, HR-admin scope, compensation exposure, or medical payload leakage through each channel and persistence/telemetry boundary.
3. **Action coverage gaps:** `REQUEST_INFO`, manager inactivity recovery, HR proxy decision, ticket cancel/edit, stale/expired action token, concurrent decisions, and ambiguous write recovery are described or implied but not fully tested.
4. **NFR verification gaps:** NFR-001 to NFR-015 do not have a linked complete verification suite. Latency, availability, job dispatch window, connector failure, actionable alerting, data minimization, configuration changes, metric definitions, and interoperability need named checks and owners.
5. **Architectural omissions:** Time-clock engine, notification/email dispatcher, HR queue implementation, telemetry/alert backend, and audit tamper-evidence/retention mechanism are absent or underspecified in the component topology. The architecture includes Storage/Search/Foundry and separated Cosmos stores, but these remain intended components, not verified deployment.
6. **User experience gaps:** No HR-admin escalation queue journey, no business-hour reminder/escalation sequence, no error flow for unavailable/stale HRIS, no direct-report authorization failure journey, and no accessibility acceptance criteria in the PRD.
7. **Marketplace readiness gaps:** No confirmed Agent Store agent type/package, Partner Center offer design, managed-app deployment artifacts, commercial ownership decision, tenant consent workflow, support model, or publish gate evidence.
8. **Product outcomes:** PRD lists baselines as “to be measured” and targets for deflection, resolution, SLA compliance and escalations; instrumentation, attribution, cohort/denominator rules, privacy, and target approval are not demonstrated.
